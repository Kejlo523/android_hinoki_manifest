# LineageOS 17.1 for Sony Xperia XA1 Dual (G3112)

Complete source manifest for the unofficial Android 10 port for Sony Xperia
XA1 Dual (`hinoki`, G3112).

## Build

Start with a normal LineageOS 17.1 build environment:

```bash
repo init -u https://github.com/LineageOS/android.git -b lineage-17.1
mkdir -p .repo/local_manifests
curl -L https://raw.githubusercontent.com/Kejlo523/android_hinoki_manifest/main/local_manifest.xml \
    -o .repo/local_manifests/hinoki.xml
repo sync -c -j$(nproc --all)

source build/envsetup.sh
lunch lineage_hinoki-userdebug
mka bacon
```

The flashable ZIP is written to `out/target/product/hinoki/`.

For a release signed with your own keys, use the checked-in wrapper after the
build (paths below are examples):

```bash
bash tools/sign-release.sh /path/to/lineage \
    /path/to/lineage/out/target/product/hinoki/obj/PACKAGING/target_files_intermediates/lineage_hinoki-target_files-eng.user.zip \
    /path/to/private-keys /path/to/ROM/lineage-hinoki-release.zip
```

The wrapper replaces the OTA/recovery verification certificates, signs platform
and NetworkStack packages, emits matching standalone boot/recovery images, and
explicitly enables `addon.d` backup/restore.
Installed GApps with their own `addon.d` script therefore survive an in-place
update. This does not restore Google apps after formatting system/data. Keep
private keys outside Git and use the same keys for subsequent releases.

Use `local_manifest-pinned.xml` instead of `local_manifest.xml` when you need
the device-specific revisions used for the 2026-09-21 V27 build. Upstream
LineageOS projects are still selected by the base manifest.

## Boot ramdisk and Magisk

V27 retains the existing system-as-root filesystem and partition layout, but
boots through Android 10's static first-stage `init` in a real boot ramdisk.
`BOARD_BOOT_RAMDISK_WITH_SYSTEM_ROOT` opts into this behavior in the device,
build and init trees. The kernel command line no longer contains
`skip_initramfs` or a hard-coded root partition. First-stage init mounts the
existing system partition and switches root; no repartitioning or data wipe is
needed for this change. The kernel itself is unchanged from V26.

Both the local build and release-signing reconstruction preserve the ramdisk.
The signing wrapper checks this before generating the OTA. `boot.img` is a
normal Android v0 boot image generated by `mkbootimg`, not a separately
private-key-signed boot container. Our private release keys sign the OTA ZIP,
APK packages and recovery's trusted OTA certificates; the bootloader must be
unlocked.

The ROM does not automatically grant applications root. Magisk **v28.1** has
been tested on this device with SELinux enforcing. Earlier ramdiskless boot
images are not supported by the installer below. SuperSU and other Magisk
versions have not been validated.

For Lineage Recovery, build a signed wrapper around an official Magisk APK:

```bash
bash tools/build-magisk-recovery.sh /path/to/lineage \
    /path/to/Magisk-v28.1.apk /path/to/private-keys \
    /path/to/ROM/Magisk-v28.1-hinoki-2SI-RELEASE.zip
```

Install the V27-or-newer ROM first. Then use recovery's **Apply update > Apply
from ADB** and `adb sideload /path/to/Magisk-v28.1-hinoki-2SI-RELEASE.zip`.
Use the same release key that recovery trusts. The wrapper checks the device
and ramdisk, invokes the official installer with `/system/bin/sh` (this
recovery has no `/sbin/sh`), and leaves the embedded APK byte-for-byte unchanged.
It requests preservation of existing verity/encryption settings. After boot,
open the Magisk app and explicitly allow each application's superuser request;
being a system app alone does not grant root. Flashing an unpatched boot image
removes the boot-side root patch.

Regression tests for the release tools (after building the host tools):

```bash
PATH="$PWD/out/host/linux-x86/bin:$PATH" python3 -m unittest discover \
    -s build/make/tools/releasetools -p test_boot_ramdisk.py -v
```

## Device baseline

- Device: Xperia XA1 Dual G3112
- Required stock firmware baseline: `48.1.A.2.112`
- Android: 10 / LineageOS 17.1
- Kernel: [android_kernel_sony_mt6757](https://github.com/Kejlo523/android_kernel_sony_mt6757/tree/lineage-17.1-hinoki)
- Build-specific kernel commit: [`7d74b285`](https://github.com/Kejlo523/android_kernel_sony_mt6757/commit/7d74b28506bdaf4c025b602b6a50ad58f017ed5a)
- Google apps are not included.

## Current compatibility notes

This is still an unofficial alpha port built around Sony/MediaTek Oreo vendor
components. The tree contains the compatibility work for camera, audio, RIL,
storage, Wi-Fi, HWC and media used by the current ROM.

- Hardware MTK video decoders are disabled because their Oreo Vcodec ABI
  crashes Android 10 media services. Android software decoders are used.
- Screen recording uses the Android software AVC encoder.
- MTP uses the legacy MediaTek gadget path with synchronized teardown and has
  been verified with repeated checksum-matched transfers.
- NFC is deliberately limited to stable NFC-A polling. Android Beam/P2P and
  the parallel NXP extension HAL are disabled to avoid controller hangs.
- The device currently uses the primary SIM path; dual-SIM behavior remains
  incomplete.
- SELinux is enforcing with the legacy MediaTek vendor domains restored.
- GNSS data directories are created by platform init after a data wipe. The
  legacy AGPS BIO callbacks are adapted to Android 10 BoringSSL, and the GNSS
  shutdown compatibility preload remains active under enforcing SELinux.
- Satellite fixes and SUPL assistance have been verified on the device. Full
  battery endurance still requires an unplugged idle test.
- Wired headphone detection uses MTK ACCDET input switch events rather than
  the absent `h2w` sysfs switch. The framework overlay is included in the ROM,
  so the fix does not depend on a runtime mount or survive only until a wipe.
- Device Info HW, Kernel Adiutor and DuckDuckGo are included as system apps.
  For root access, install Magisk separately and grant access in its manager.

Contributions and device logs attached to reproducible bug reports are
welcome.
